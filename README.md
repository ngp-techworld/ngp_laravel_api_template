# NGP Laravel API starter

The starting point for every NGP TechWorld backend: a Laravel 13 JSON API under `/api/v1` with
Sanctum sign-in (SPA cookie and bearer tokens), PostgreSQL, Pest, Pint, Larastan and Scramble, plus
one example feature (a paginated `items` list) wired end to end the NGP way.

## Parts

| Folder | What | Stack |
|---|---|---|
| `.` (becomes `backend/` in a product repo) | REST API (`/api/v1`) | Laravel 13, PHP 8.4, PostgreSQL 16 |

The React (`ngp_react_vite_template`), Next.js (`ngp_nextjs_template`) and Flutter
(`ngp_flutter_template`) starters talk to this API; the shared contract is in [docs/API.md](docs/API.md).

## Start a product from this template

1. Create the repo with GitHub's "Use this template" (or copy this folder to `backend/`).
2. Rename per product:
   - `composer.json` `name`: `ngptechworld/<product>-backend`, and `APP_NAME` in `.env.example`.
   - The `app:` prefix of `app:create-user` (`app/Console/Commands/CreateUserCommand.php`) to
     `<product>:create-user`.
   - Databases `app` / `app_test` to `<product>` / `<product>_test` in `.env.example`,
     `phpunit.xml` and `.github/workflows/ci.yml`.
3. Replace the `Item` example with your first real feature
   ([ARCHITECTURE.md](ARCHITECTURE.md), "إضافة ميزة جديدة").

## Run locally

Requirements: PHP 8.4 at its latest patch, at least 8.4.27 (`pdo_pgsql`, `intl`, `zip`, `bcmath`),
Composer 2, PostgreSQL 16 with two databases, `app` and `app_test`. `composer install` refuses
older PHP releases because they have known security issues; raise the floor in `composer.json`
when a new PHP security release comes out.

```bash
cp .env.example .env && composer install && php artisan key:generate   # then set DB_* in .env
php artisan migrate --seed       # local only: demo@example.com / password with 30 items
php artisan serve                # http://127.0.0.1:8000, API docs at /docs/api
```

- Real users (staging/production): `php artisan app:create-user` (`--admin` for an admin). Seeders
  never create users outside `local`.
- Background jobs and queued mail: `php artisan queue:work`.

## Tests

```bash
vendor/bin/pint --test && vendor/bin/phpstan analyse && php artisan test
composer audit
```

Tests run on PostgreSQL (`app_test`), never SQLite. CI runs the same steps on every PR.
